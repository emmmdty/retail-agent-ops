# 7.2 测试覆盖盲区

## 任务

审查测试套件，找出核心逻辑未被测试覆盖的地方、测试本身的 bug、和测试的脆弱性。

## 需要读取的文件

- `tests/` 目录结构
- 核心测试文件
- `tests/test_fault_matrix.py`
- 治理测试代码

## 找什么

1. **核心路径的测试覆盖**：Agent 执行循环、tool parser、评测脚本、门禁逻辑——每个核心模块是否有对应的测试？

2. **边界条件测试**：最大步数、空输入、格式错误输入、超时——这些边界条件是否有测试？

3. **测试本身的 bug**：测试中断言是否正确？是否有测试通过了但实际逻辑有错的情况？

4. **测试的确定性**：测试是否完全确定性（无随机种子依赖）？是否有 flaky test？

5. **治理测试的有效性**：治理测试声称断言"配置未被篡改"——测试逻辑是否真的能检测到篡改？还是只检查了表面？

6. **测试的维护成本**：测试数量是多少？每次改动需要跑多少测试？测试运行时间是多少？
