# 3.2 训练数据的质量问题

## 任务

审查训练数据的生成、筛选、统计，找出数据质量问题。

## 需要读取的文件

- 数据生成代码
- 数据统计信息（manifest 中的统计字段）
- `docs/EXECUTION_PLAN.md` R2、R6、R9 的数据记录
- `docs/R9_PHASE_B_RESULTS.md`

## 找什么

1. **数据量是否充足**：训练集有多少条？对于 QLoRA-SFT 来说这个量是否足够？有没有过拟合风险？

2. **数据筛选的副作用**：过滤无效轨迹时，过滤率是多少？是否过滤掉了某些重要的边界案例？

3. **类别分布**：各业务场景（订单查询、退款允许、退款拒绝、异常恢复、政策冲突）的数据量是否均衡？R7 发现的分布偏移是否只在一个场景存在？

4. **R9 的数据膨胀**：从 240 条扩到 1920-2240 条——新增数据的独立性如何？是否有大量排列组合产生的伪多样性？

5. **teacher 模型的质量天花板**：DeepSeek 生成的轨迹质量如何验证？是否有 oracle 回放验证？teacher 自身的工具调用正确率是多少？

6. **"自变量不纯"的实际影响**：sft 行数和梯度步数同时改变——这意味着我们无法区分是数据量增加还是训练时长增加带来了效果变化。这个结论是否已在文档中明确标注？
