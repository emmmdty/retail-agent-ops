# 3.1 数据隔离的实际漏洞

## 任务

验证 train/dev/holdout 的隔离机制，找出实际存在的隔离漏洞或潜在泄漏路径。

## 需要读取的文件

- `manifests/` 目录下所有文件
- 数据生成代码
- 数据加载代码
- `docs/EXECUTION_PLAN.md` R2、R6、R7 的数据治理记录

## 找什么

1. **manifest 的生成逻辑**：manifest 是手写还是代码生成？生成代码是否被测试覆盖？

2. **哈希校验的实际执行**：`phrasing_exclusivity.json` 是否在训练前被自动校验？还是只是一份静态文件？

3. **数据加载时的隔离检查**：加载训练数据时，代码是否会检查与 dev/holdout 的重叠？还是完全依赖 manifest 的正确性？

4. **teacher 模型的泄漏风险**：teacher 在生成 train 数据时，是否可能接触过 holdout 的任务定义？如果 teacher 的 prompt 中包含了任务模板，是否与 holdout 任务共享模板？

5. **R7 发现的 5 倍分布偏移**：`refund_denied_window` 的训练/测试分布严重不均——这个分布检查是否有自动化工具？还是会每次人工发现？

6. **哈希清单的完整性**：`phrasing_exclusivity.json` 是否覆盖了所有需要检查的素材？是否有遗漏的重叠路径？
