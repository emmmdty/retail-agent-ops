## 一、为什么合并立项

三个改动各自的证据链成本都是「新 dataset_version + 重新冻结 + base/candidate
全部重跑 + 新封存集」：

| # | 改动 | 动机（已有证据） | 单独做的成本 |
|---|---|---|---|
| 1 | **难度分层切分**（PITFALLS 入口 7） | 冻结切分按 `sha256(family)` 不看难度：`refund_denied_window` 的 margin ≥10 family 占比 train 10% vs holdout 50%（5.0×）；`refund_denied_window` dev 只覆盖 4/7 档、`refund_denied_duplicate` 2/7 档；`offset = 0` 整个冻结集从未生成（`POLICY_BOUNDARY.md` §2） | 全价 |
| 2 | **`max_steps` 4→6**（C4 提案 1） | `refund_recovery` 需要 3 次工具调用只剩 1 步余量，行为对、预算不够的假阴性有真实占比；R8 根因 3 | 全价 |
| 3 | **`reason` 语义等价、口径 A**（C4 提案 2） | 语义可辩护但不在 gold 枚举的理由被判 `invalid_call`（绝对门 Literal[0]）——「行为可辩护、判分器不容忍」的假阴性；口径 A 把模糊性显式写进任务契约，避免口径 B「判分器替模型说话」 | 全价（口径 A 动数据集 + verifier） |

合并 = 付**一次**全价拿到三项收益。拆开做则同一批重跑付三次。
**代价**：三项同时上线使单变量归因变弱——用「分阶段验收」（§五）弥补：
重建后先跑诊断面拆分读数（分层效果单独可读），再做训练与发布判定。

## 二、分层算法（设计）

切分对象不变：每场景 35 个 family（v1 冻结生成器的 family 概念），切分键从
`sha256(family)` 换成**分层分层键**：

1. 对每个 family 计算**难度标量**：拒绝类场景 = `margin`（`refund_deadline −
   current_day` 离 0 的距离），放行类 = 0（单一难度档），恢复/复合类 =
   gold 序列步数。标量离散成 **7 个难度档**（margin 档 1/2/3/5/7/10/14 + 新增 0 档，见下）。
2. **每档内部**再按 `sha256(family)` 排序——档内顺序仍是确定性的、无人工挑选。
3. 按 `档内序` 轮转分配 train 20 / dev 5 / holdout 10：**每个难度档在三个
   split 中都出现**（比例尽量接近 20/5/10），消除 5.0× 偏移。
4. **新增 `margin = 0` 档**（`offset = 0`，判定分界日，政策判放行）：v1 的
   margin 网格 `{1,2,3,5,7,10,14}` 从未生成过分界日。重建网格加入 0
   （`refund_eligible` 用 `20 + margin` 含 0；denied 侧不变），并在 train/dev/
   holdout 各分配固定份额。探针 §4 读数表明模型对 offset 0 已能判对（n=8），
   补数据是让训练分布覆盖判定分界，而非修一个已观测的失败。
5. **反泄漏断言**（沿用 R7 先例，机器守卫）：分层键使用的 margin 值与探针
   评测网格的映射关系进测试——train 出现的 margin 档不得让 dev/holdout 的
   同格同措辞任务可被「背答案」命中；family 身份在三个 split 间互斥。

**验收（CPU 可测）**：新切分上逐场景输出 margin 档覆盖表 + 难度质量分布表，
断言每个场景 dev/holdout 覆盖全部档位、margin ≥10 family 占比 train:holdout
比值 ∈ [0.8, 1.25]（对照现状 5.0×）。

## 三、新配额与规模

| 维度 | v1 冻结（现状） | 重建提案 |
|---|---|---|
| 场景数 | 8（+v4 两次扩展的场景族） | 沿用 v4_20260905 的场景集（含 rtc_stepwise，D1 已验证有效） |
| 每场景 family | 35（train 20/dev 5/holdout 10） | 不变；切分换分层键 |
| margin 网格 | 7 档，无 0 | 8 档（+0），每档份额进三分 |
| `max_steps` | 4（rtc 5） | **6**（rtc 7）——sealed config Literal 同步 |
| `reason` 字段 | 单一枚举 | **可接受集合**（任务侧，口径 A）：user_request 的事实标签映射到 ≥1 个可接受理由，verifier 按集合判定 |
| teacher | v4-004/005（mimo，~600–640 任务） | 全量重采（同 mimo-v2.5 端点） |

**teacher 预算（按 D1 方案甲实测外推）**：v4 场景集任务数 ≈ 640 + 8 档网格
增量（每场景新增 1 档 × family 份额）≈ **约 700 任务 × ~2.9K tok/任务 ≈
2.0M tokens（mimo-v2.5）**。采集前 `--dry_run` 估量、分场景审措辞先验
（PITFALLS #5）、分片覆盖断言 `min_per_partition_intent` 与回环分类丢弃率
（bank-004 先例）全部沿用。费用逐次记 progress.md。

## 四、判读规则（草案——立项后预注册正式稿，先于一切运行提交）

**分层切分本身的效果先用诊断面验收（不训练）**：

- 覆盖表/难度分布表全档覆盖 + 5.0× → ~1.0×（CPU 断言）；
- Oracle 自洽：新任务集 gold 序列全可解、零违规、DENY 场景在环境层真的 deny、
  请求携带 gold 所需参数（E2 四层修复的既有断言全量沿用）；
- `max_steps=6` 后 `refund_recovery` 的 `step_limit` 假阴性占比显著下降
  （诊断面读数，不设训练阈值）。

**训练后的候选验收（三面 + 新封存，判读阈值立项时冻结）**：

1. dev（新冻结集，模板内）：候选 ≥ base 的幅度与历史 GO 同量级；
2. OOD（既有 v2 系列分片，措辞分布外——**与训练面不同源**，R7 纪律）：
   按既有绝对门 `ood_task_success_min ≥ 0.70` 系列口径；
3. 新封存 holdout（v1.4 口径是否启用单独问用户）：逐门 PASS/FAIL，
   重点读数 = `policy_violation_count_max = 0`（绝对门）在重建分布下能否达到；
4. **无论结果**：不重跑、不换素材；结果不得反馈进任何调参。

## 五、与既有口径的可比性断裂清单（全部如实披露）

| 既有口径 | 断裂方式 | 善后 |
|---|---|---|
| dev 60（v1/v4 冻结集）与全部 dev 配对读数 | 任务集内容变化，`budget`/`task_ids` 配对校验拒绝混用 | 新旧口径**并列陈述**，不换算 |
| 封存 holdout 120（观测 1–7） | 新 dataset_version ≠ 旧版本；配对不可跨 | 台账标注「口径终止于观测 N」 |
| 探针读数（§4/§6） | 探针网格本身不变（offset 轴不变），但训练分布变了 | 探针可继续用；历史读数标注训练数据版本 |
| OOD v2/v2.2/v2.3 分片 | 任务集不变，候选可比性**保留**（同集合同条件）；基座读数不受影响 | 可继续用于跨候选比较 |
| sealed config `Literal[5]`、`budget` 字段 | max_steps 4→6 改 Literal | 新 Literal 只进新 dataset_version 的配置 |
| `evidence_complete` / replay | verifier 按集合判定 reason → 重放语义变化 | verifier 版本化 + 旧证据复算断言不变（口径 A 只对新数据集生效） |
| 历史候选（sft-008 等） | 不能直接在新数据集上「续评」——需在新训练分布上重训 | 发布候选历史结论保留，不迁移 |
