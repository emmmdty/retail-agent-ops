# 分布外评测：120/120 **不是**泛化，而且训练把表面鲁棒性变差了

**这份读数对刚拿到 GO 的候选是负面的，必须与那个 GO 一起引用。**

## 由来

评审 P0-1：`domain/formal_tasks.py:_user_request` 只有 **6 场景 × 2 变体 = 12 句中文
模板**，train / dev / holdout 共用它们。五维指纹保证的是"没有逐字重复"，
**不是"没有分布重叠"**。因此封存 holdout 上的 120/120 只能说明**模板内插值成功**。

这个集合是那句话的对照组：60 条、三类各 20，**独立 dataset artifact**
（`retail_ops_ood_v1_20260815`，自己的 manifest），冻结数据集一个字节不变。

## 结果（gpu-5090，`code_commit` `d57f17f`，manifest `afc41351…`，LOG-20260816-01）

| | base（零训练） | **合并版候选**（第四次观测拿到 GO 的那一份） |
|---|---|---|
| **封存 holdout（模板内）** | 0.8583（103/120） | **1.0000（120/120）** |
| **分布外（模板外）** | **0.2167（13/60）** | **0.5833（35/60）** |
| 政策违规 | 12 | **0** |
| 非法调用 | 44 | 38 |
| `average_tool_calls` | 0.7833 | 1.2000 |
| schema 合规率 | 0.5165 | 0.6545 |
| 可重放 | 60/60 | 60/60 |

**同一个候选，从 100% 掉到 58.3%。** 这就是"120/120 不是泛化证据"的直接证据。

## 逐类别：训练不是均匀地变好，而是一半变好一半**变差**

| 类别 | base | 合并版候选 | 差 |
|---|---|---|---|
| `scenario_ood`（工具面做不到的请求 + 多实体） | 0.00 | **0.75** | **+0.75** |
| `adversarial`（错订单号 / 脏字段 / 缺字段 / 工具诱导） | 0.35 | **1.00** | **+0.65** |
| `expression_ood`（口语 / 寒暄 / 错别字 / 中英夹杂 / 极简） | 0.30 | **0.00** | **−0.30** |

**表达类归零，而且比零训练基座更差。** 逐 kind 看最刺眼的一条：

| kind | base | 候选 |
|---|---|---|
| `code_switch`（中英夹杂） | **1.00** | **0.00** |

## 这些数字说明什么

**1. 训练教会的是"这种措辞出现时该退款"，不是"什么时候该退款"。**
候选在 `expression_ood` 上的 20 条失败**全部**是 `premature_final_response`——
正是 R3 那个老失败模式。换一种说法，训练过的模型就退回去了。基座反而能处理
中英夹杂（`code_switch` 1.00 → 0.00 是本文件最尖锐的一条对照）：在 400 行中文模板上
做 SFT，把基座原有的多语言与口语鲁棒性挤掉了。

**2. 但训练确实教会了真东西。** `scenario_ood` 0.00 → 0.75、`adversarial` 0.35 → 1.00：
候选学会了**在工具面做不到时查证后拒绝**（部分退款 / 换货 / 政策通融三类全对），
也学会了在脏数据、缺字段、被诱导调用不存在工具时不乱来。政策违规 12 → 0。
这些都不是模板匹配能解释的。

**3. 两者都不会处理多实体请求**（`two_orders` 双双 0.00）。这是能力缺口不是回归。

**4. 因此"SFT 有没有用"这个问题问错了。** 正确的说法是：这次 SFT 用**表面形式的
鲁棒性**换来了**任务结构与安全性**。在冻结 holdout 上只看得见换来的那一半，
因为那 120 条与训练集共用同一批 12 句模板。

## 对第四次 GO 的影响

**GO 本身不改。** 它是对**封存 holdout** 的判定，那 120 条上候选确实 120/120、
延迟确实达标，门禁测的就是它设计要测的东西。

**但这份读数必须与那个 GO 一起出现。** 门禁从来没有覆盖分布外表现——
`SPEC.md` §6 的五（八）项里没有一项测表面形式鲁棒性。一个通过了全部自动门禁的候选，
在模板外的表达变化上是 **0/20**，且**比不训练还差**。

**这条改变后续做法**：候选选择与发布判定都应当把分布外读数作为**必看项**，
哪怕它暂时不是门禁。把它做成门禁需要先解决"OOD 集合本身会不会被过拟合"的问题，
那是独立决策。

## 这个集合**不**声称什么

- **表达变体是作者手写的模板库**，不是 LLM 改写的——两台机器都没有配置
  `TEACHER_LLM_*` 凭据。因此它度量的是"对我想到的那些表面变化的鲁棒性"，
  **不是"对任意真实用户输入的鲁棒性"**。真实分布只会更宽。
- **n = 60（每类 20）**，CI 宽度约 ±12pp。类别间的大差距（0.00 vs 1.00）远超噪声，
  但不要用它分辨小幅差异。
- **它不是封存集合**：公开、可反复读、可分析。因此它的读数**会**随着被用于改进而
  逐渐失去独立性——用它选候选就等于开始过拟合它。这一点与封存 holdout 的纪律不同，
  必须自觉。
- 只跑了两档（零训练基座、合并版候选）。未合并候选与 1.7B 未在此集合上评测。
