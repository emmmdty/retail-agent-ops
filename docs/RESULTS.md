### 封存 120 条 holdout（Qwen3-4B）

> 逐次读数、判定与每个 GO 必须一起说的限制，见
> [`docs/HOLDOUT_LEDGER.md`](docs/HOLDOUT_LEDGER.md)（唯一事实源）。

| 观测 | 候选 | task_success | 政策违规 | 非法调用 | p95 比值 | 判定 |
|---|---|---|---|---|---|---|
| 1（2026-08-11） | R3，attention-only | 0.7500（90/120） | 16 → **0** | 41 → **0** | 1.0870 | **NO-GO**（`success_delta` −0.0333） |
| 2（2026-08-14） | R4 `sft-006`，全 linear | **1.0000（120/120）** | 11 → **0** | 5 → **0** | **1.8774** | **NO-GO**（延迟） |
| 3（2026-08-15） | 同上，代码冻结后复现 | **1.0000**（逐位相同） | 0 | 0 | 2.0250 | **NO-GO**（延迟） |
| 4（2026-08-15） | **同一份权重，合并进基座** | **1.0000** | 0 | 0 | **1.1265** | **`GO` / candidate（merged）** |
| 5（2026-08-17） | **R6 `sft-008`（措辞增强），合并形态** | 0.9750（**117/120**） | 11 → **2** | 0 | **1.0203** | **`GO` / candidate（merged）** |
| 6（2026-08-17） | **同一份配置，只换训练 seed 重建** | 0.9417（**113/120**） | 11 → **7** | 0 | 1.0902 | **`GO` / candidate（merged）** |

**第 5、6 次是同一份 SFT 配置的两次训练运行，只差 `--seed`。** 它们在这 120 条上
分别是 117/120（2 次政策违规）与 113/120（**7 次**）——**同配置两次运行，
安全类失败差了 3.5 倍**。两次都 `GO`，但第 6 次的 `success_delta_ci_lower` 只有
**+0.0083**（第 5 次是 +0.0583），几乎贴着 0。

**7 次失败全部是同一个签名**（给已过退款期限的订单退款），
那一类 20 条错了 7 条、其余五类全部 20/20。**门禁比的是与 base 的差
（11 → 7 即通过），所以一个违规更多的候选照样能过——这是门禁定义的性质，
写在这里而不是藏起来。通过门禁 ≠ 可以上线。**

**GO 归因于部署形态，不是模型**：未合并候选对同一份 base 重算仍是 1.9219 FAIL。
延迟代价已拆开——调用次数只增 14.6%，**单次调用耗时 1497 → 2971 ms（1.985×）**，
来自全 linear LoRA 的前向开销。

### dev 60 条：prompt × 容量 × 模型规模

| | 零训练 | attention-only | 全 linear layer |
|---|---|---|---|
| **Qwen3-4B**，原 prompt | 48/60 | 45/60 | **60/60** |
| **Qwen3-4B**，新 prompt | 54/60 | 55/60 | **60/60** |
| **Qwen3-1.7B**，新 prompt | 44/60 | **58/60** | 45/60 |

**1.7B 上方向相反**：全 linear 的 15 条失败**全部**是"该拒绝却没拒绝"
（`refund_denied_ownership` 10/10 全灭，`average_tool_calls` 1.27→2.08）——
容量过剩被训练数据 2:1 的执行偏向带跑。**结论是容量必须与规模匹配，不存在"越大越好"**，
且数据配比与容量**耦合**，不能当作两个独立旋钮。

### 泛化修复：对未见过的措辞更鲁棒了，以及它的账单

诊断出「表面形式 → 动作」的捷径后，用 LLM 生成的措辞池做训练增强
（只改 user 第一句话，工具调用与目标状态一个字不动）。措辞按
`sha256(措辞+固定盐)` **确定性三分**，训练用的与评测用的**逐条互斥**（ADR 0005）——
不是构造上应该互斥，而是**直接读真实训练文件比对过**：训练分片的 147 条里
142 条确实进了 `sft.jsonl`，评测分片的 **0 条**进了。

**封存分片（每份素材只观测一次，代码冻结后跑）**，状态空间与冻结契约同宽。
**做了两份独立生成的措辞池**——一份素材上的满分分不清「模型鲁棒」与「那批说法恰好好做」：

| 运行 | `bank-002` 分片 | **`bank-003` 分片（全新素材）** |
|---|---|---|
| 零训练基座 | 0.7667 | 0.7333 |
| 旧候选 `sft-006` | **0.7167**（**低于基座**） | 未测 |
| **新候选 `sft-008`** | **1.0000** | **0.9833** |
| `sft-008` 换 seed 重建 | 未测 | **0.9833** |

旧候选在 bank-002 上**低于零训练基座**——这正是要修的那件事。
**新候选的正确写法是「两份独立措辞池上分别 1.0000 与 0.9833」，不是单点满分。**
bank-003 那一份八种说法风格全部在场，而 bank-002 只有七种、`terse` 一条都没有——
它测到了上一份结构上测不到的东西。**但样本量比任务数小得多**：60 条任务只用到
**35 条不同措辞**，按措辞去重后最小的那一格是 **n=1**（`terse` 那 4 条其实是
同一句话配了四个订单号）。任务级的 n=3 是**报大了的那个数**；
对「没见过的措辞」这个命题，真实下限是 1。

**独立迁移检查**（OOD v1：作者手写、生成过程完全不同、**从未用于选择**）：
`expression_ood` **0.00 → 1.00**（20 条 = 五子类 × n=4），总分 0.5833 → **0.8667**。

**账单**：模型变得更倾向执行，于是「不该动手时也动手」——封存 holdout 上
**同配置两次训练分别有 2 次与 7 次政策违规**（旧候选 `sft-006` 是 0 次，
但那是**单次训练运行**——我刚证明这个指标在同配置两次运行间能差 3.5 倍，
所以拿一个 1 运行的点去比一个 2 运行的分布，本身就是弱比较），
全部是同一个签名「给已过退款期限的订单退款」；
OOD v1 的 `scenario_ood` 从 0.75 掉到 **0.60**（`partial_refund` 1.00 → **0.00**）。
收益与代价来自同一个改动。

**这笔账单一开始被我记小了。** R6 只报了 2 次，那是两次运行里较好的一次；
而且当时归因为「措辞增强的确定代价」，论据是两个候选失败签名相同——
**但它们共用一个训练 seed**。详见[独立重建复验](docs/REBUILD_VERIFICATION.md)。

**一个必须说的更正**：这个封存分片的**第一版是有缺陷的**——它的状态空间比训练/dev 更窄
（1 个订单 vs 1–5、1 种期限余量 vs 7、3 种订单状态 vs 7），也就是更容易，
而文档写着「唯一自变量是说法」。**这是外部审阅发现的，不是我自己发现的。**
修正后换一份**全新措辞池**重测才有上表；旧分片退役，其唯一一次读数保留在
[`docs/OOD_SEALED_LEDGER.md`](docs/OOD_SEALED_LEDGER.md)。

详见 [`docs/GENERALIZATION_FIX.md`](docs/GENERALIZATION_FIX.md)。

**这条失败模式后来被定位到了具体的状态区域。** 一个沿「退款截止日 − 当天」扫描的**政策边界探针**显示：候选在 15 个偏移量里 14 个判定全对，**只在「已过期 14 天」这一格塌到 0.375**——而零训练基座在那一格是 1.00，**但那不是合规，是它根本不动手**（基座在应放行的一侧只有 0.00–0.38）。针对性的数据修复在同源措辞的评测面上改善、在措辞分布外的评测面上退化，**按事先写定的规则判负，候选未更换**。详见 [`docs/POLICY_BOUNDARY.md`](docs/POLICY_BOUNDARY.md)。

### 独立重建复验（SPEC §6 第 6 条）——做了两轮，**最终候选也在内**

同一份配置、同一份数据、同一个基座、同一组超参，**只换 `--seed`** 重训，
再对同一份 base 证据做配对评测。

**第一轮（`sft-006`，仅 dev）**：

| 运行 | seed | dev task_success | 政策违规 |
|---|---|---|---|
| `base-002`（零训练） | — | 0.9000（54/60） | 5 |
| 原候选 `sft-006` | 0 | 1.0000（**60/60**） | **0** |
| **重建 A** | **0（同 seed）** | 0.9667（**58/60**） | **0** |
| **重建 B** | 1 | 1.0000（**60/60**） | **0** |

**同 seed 产不出同一份权重**（训练代码零改动、数据哈希一致、解析后配置只差两行输出路径）。
所以 **「60/60」不是常数**，它有 ±2 的运行间波动，且波动**全部**落在 `refund_recovery`。
**训练是本项目唯一不能逐位复现的环节。**

**第二轮（`sft-008`，最终候选，dev + 分布外 + 封存 120）**：第一轮做在 `sft-006` 上，
而最终候选是 `sft-008`——「你的最终候选没被独立重建过」这个缺口一直开着。

| 判据（**跑之前写定**） | 结果 |
|---|---|
| **A** dev 严格高于零训练基座 | ✅ 重建 **60/60、0 违规**（原候选 58/60、2 违规） |
| **B** 在**全新生成**的措辞池封存分片上 ≥ 基座 +0.15，且与原候选相差 ≤ 0.10 | ✅ **+0.2500** 与 **0.0000**（两者同为 0.9833，基座 0.7333） |
| **C** 封存 120 的门禁判定（**刻意不参与「是否复现」的认定**） | `GO`，两套口径；但 113/120、**7 次政策违规** |

**判据 A 与 B 都成立 → 复现。** 但"复现"的含义要精确：复现的是**方向与量级**，
**不复现的是逐条行为**——权重逐位不同、失败的具体条目不同、
安全类失败在同配置两次运行间差了 3.5 倍。

**这一轮修正了 R6 的一条归因**：R6 说那 2 次政策违规是「措辞增强本身的代价」，
论据是两个只差 oversample 的候选失败签名完全相同——**但它们用的是同一个训练 seed**。
换 seed 后 dev 上的违规是 0、封存 120 上是 7。能支持的表述只剩：
**措辞增强让这类违规变得可能，次数在运行间波动很大。**

**而且 dev 与封存集把这两次运行排成了相反的顺序**（dev 上重建更好，封存集上原候选更好）——
`refund_denied_window` 在 dev 只有 10 条，看不见 7/20 这个量级的问题。
**这是「dev 不能替代封存集」的一份事后证据。**

详见 [`docs/REBUILD_VERIFICATION.md`](docs/REBUILD_VERIFICATION.md)。
