## 2. 任务 A：第三个训练 seed —— 把「波动」从 n=2 升级成 n=3

### 为什么这是本轮最有价值的一件事

项目现在最弱的一句话是「政策违规次数在运行之间波动」。它的全部证据是 **n=2**：
同配置两次运行，在封存 120 上分别是 **2 次**和 **7 次**违规。
两个点无法区分「正常抖动」和「其中一次是异常」，而这个数直接支撑
`policy_violation_delta` 门禁。头条区间 `58–60/60`、`113–117/120` 同样是两点极差，
不是分布。

**跑第三个 seed 是唯一能把「我承认它有波动」升级成「我量了它的波动」的做法。**
这也正是去绝对化的正解：用实测区间替换单点满分。

### 预注册（**必须在跑之前提交**）

重写 `task_plan.md` 并 commit，内容至少包含：

1. **本轮唯一自变量是 `--seed 2`**，训练配置与 `sft-008` / 重建 seed 1 逐字节相同
   （用 `git log` 断言该配置文件未被改动，参考现有
   `tests/test_retail_ops_r7_rebuild.py::test_the_rebuild_uses_the_untouched_training_config`）。
2. **目的写死为「方差刻画」，不是候选选择。** 明确写：
   **无论 seed 2 读数好看还是难看，都不更换发布候选，`sft-008` 保持不变。**
   这一句是本轮合规性的核心——封存集结果永不反馈进选择，观测次数放开了，这条没放开。
3. 运行清单与输出目录（每个正式运行用新目录，不覆盖已有运行）：
   dev 冻结集、OOD 分片、封存 120（base + merged candidate 两侧，因为
   `SEALED_PAIRING_FIELDS` 含 `code_commit`，新提交强制两侧重算）。
4. **报告口径事先写死**：三次运行后，dev / 封存 120 / 政策违规
   一律以 `min–max（n=3，同配置仅换 seed）` 表述，
   并同时给出三个点值。**不许事后挑口径。**
5. 观测必须发生在代码冻结提交之后。

## 3. 任务 B：精简治理测试 —— 让测试数下降

`tests/test_project_governance.py` 及相关文件里有相当比例是前几轮堆出来的
Markdown 字符串守卫。面试官看到「1094 个测试」里大批是 grep 文档，是**减分项**。

**做法**：

1. 先量化：统计 `tests/` 下有多少测试实际断言的是文档字符串而非代码行为
   （建议按文件与函数列表输出到 scratchpad，不进 Git）。
2. **合并同类项**：多条钉同一份文档不同句子的断言，合并成一条参数化测试。
3. **删掉冗余**：凡是「上一位审阅者用过的句子被钉成语料」这一类，删。
   第七轮已判定这条路是死路——下一位换新句子照样漏。
4. **保留**有界高风险面上的穷举白名单（如简历 bullet 里每个数字必须有出处）。
   这类是有边界的，留着。
5. 每删一条，在 commit message 里说清删的是什么、为什么它不该在。
   **不要偷偷删**——审阅者会 diff。

**验收**：测试总数低于 1094，且 `pytest` / `ruff` / `ruff format --check` /
`mypy` 全绿，删除后 `tests/test_retail_ops_policy_projection.py` 这类**真实行为测试**
一条不少。

**红线**：不得为了降数字而删掉覆盖真实代码路径的测试。
如果删完发现某个行为失去覆盖，补一条**行为**测试，不是字符串测试。
