# DPO 入口门证据包（Phase D2，只备料不训练）

**日期**：2026-09-04
**性质**：对照执行计划 R4 的 DPO 入口条件整理既有证据，**不训练、不改判读规则、
不消耗封存观测**。是否启动 DPO 由用户裁决（决策门 #4）。

## 一、执行计划的 DPO 入口条件与当前状态

执行计划 R4 写明的入口条件：**SFT 在同一失败模式上停滞，且失败数据可以稳定形成偏好对**。

| 条件 | 证据 | 状态 |
|---|---|---|
| SFT 停滞 | R7：针对性补数据（`sft-009`）在同源探针/dev 改善、`ood_dev` 0.9833→0.9500 退化，按预注册规则判负；R9 Phase B：rtc 双订单复合动作四轮不修（oversample 反而恶化 0/10），判读规则预注册后仍未过 | **满足**（两条独立证据） |
| 失败可稳定复现 | 封存 120 上同配置两次运行违规 2 与 7 次，**全部** `refund_denied_window`（`REBUILD_VERIFICATION.md`）；探针把「该拒绝却执行」定位到 `offset −14` 单一格（`POLICY_BOUNDARY.md` §4） | **满足** |
| 偏好对可形成 | 同一状态格（`offset −14`：deadline 比当天早 14 天）下，正确行为 = 查订单后拒绝（1 步 gold），错误行为 = 执行退款（2 步）——状态相同、动作分叉，天然构成 `(chosen=拒绝, rejected=执行)` 对 | **满足（形状明确）** |
| 失败数据入口 | 探针可在 `offset −14` 稳定采样该状态；teacher（DeepSeek）在该格曾 4/56 违反同一条规则（`POLICY_BOUNDARY.md` §5），说明该格对强模型也有区分度 | **满足** |

**结论：四项入口条件全部有既有证据支撑，DPO 入口门视为已满足。**

## 二、偏好对的具体形状（设计约束，不是实现）

1. **来源状态**：政策边界探针的 `offset < 0` 各格，重点是 `offset −14`（封存违规
   全部落在这条规则上）；措辞一律取**未用于训练的分片**（交叉面 `ood_dev` 分片
   或 phrasing-bank-004 的新池）——R7 的教训：同源措辞上修出来的改善不可信。
2. **chosen / rejected**：
   - chosen = Oracle 轨迹（get_order → 拒绝答复），模型无关、逐位确定；
   - rejected = 候选模型在该状态的真实错误轨迹（执行退款）——**必须是模型自己的
     失败采样**，不能手工构造（手工构造的 rejected 会让 DPO 学到「不要执行退款」
     而不是「过期的才不能执行」）。
3. **对冲约束**：窗口内（`offset > 0`）的执行轨迹作为对照对加入，防止 DPO 把
   决策边界整体推向「多拒绝」——那正是 R7 判负的失败模式（补覆盖 = 平移不是校准）。
4. **规模预估**：违规在 120 条封存上只出现 2–7 次，但探针每个 offset 8 实例、
   可重复采样不同措辞——预期一轮 100–200 对即可支撑第一轮 DPO（SFT 数据每格
   约 8 行的教训：小而准优先于大而杂）。

## 三、判读规则草案（启动前必须先写定并提交，此处仅为草案框架）

- 主指标：封存等价物（新措辞池封存分片）上 `refund_denied_window` 类违规次数；
- 配对约束：窗口内（`offset > 0`）成功率不得退化超过预注册阈值；
- 措辞分布外读数必须与同源读数成对出现，**分布外退化优先于分布内改善**
  （R7 纪律，已是项目级规则）；
- 判定失败的候选不得以「探针改善了」作为发布理由。

## 四、成本与风险

| 维度 | 评估 |
|---|---|
| GPU 成本 | 每轮 DPO ≈ 一次 SFT 训练量级（1.7B/4B QLoRA）；采样 rejected 轨迹需要 GPU 评测若干批 |
| 数据成本 | 措辞若用新池（phrasing-bank-004）需 DeepSeek 生成，费用记 token/金额 |
| 方法风险 | DPO 在「拒绝/执行」二元边界上容易整体平移（R7 教训的直接放大）；对冲对设计是关键，且必须先写定判读规则再跑 |
| 机会成本 | 与 rtc 第四轮（D1）互不冲突：D1 修数据覆盖，DPO 修决策边界，二者机制不同 |
| 不可重试约束 | 已证伪方向清单（PITFALLS §三）里没有 DPO 本身，但「调 oversample 权重」「统一调用顺序」两条在 DPO 数据构造里同样不得复活 |

## 五、建议

- **建议启动 DPO 入口评估的下一步**：批准后先做 (a) 判读规则正式稿 + (b) 偏好对
  采样器的 CPU 实现 + 预注册提交，然后才进 GPU 采样。
- 若用户希望先看 rtc 第四轮结果再决定，两个顺序都成立；D1 与 DPO 采样共用
  探针链路，先后不影响成本结构。
- **本证据包不请求任何 GPU / 商业 API / 封存观测消耗。**
