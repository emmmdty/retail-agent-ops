# Agent 本体：能力面、可注入的四个缝、以及仍然缺的东西

2026-08-15 评审对本项目的总判断是：

> 这是一个优秀的**模型交付治理 / release engineering** 项目，但目前**不是一个 Agent
> 架构项目**。全部工程复杂度集中在证据链与发布纪律上，而 Agent 本体是一个 3 工具、
> 单轮、最多 5 步、正则解析的最小 ReAct 循环。

本文件记录这句话在 2026-08-15 之后**哪些部分不再成立、哪些仍然成立**。

## episode 循环的四个可注入缝

`core/agent/runner.py::run_episode` 现在接受四个可选参数。**四个都默认关闭**：
不传时行为与 2026-08-15 之前逐字节相同——全部已产出的评测证据都依赖这一点。

| 缝 | 作用 | 默认 |
|---|---|---|
| `system_prompt` | 由 bundle 渲染的政策卡（v1 逐字节返回冻结常量） | 模块常量 |
| `guardrail` | 与环境校验分层独立的调用前置校验 + 观测消毒 | 关 |
| `user_simulator` | 把单轮变成可澄清的多轮 | 关 |
| （env 工厂） | schema 扰动等环境侧变体 | 由调用方决定 |

**一条贯穿的约束**：这些缝改变的都是**运行条件**，因此 `replay_trajectory` 必须以
同样的条件重放。用不带 guardrail 的环境重放一条带 guardrail 的轨迹必然
`ReplayMismatch`——那不是证据损坏，是重放条件没对齐。多轮同理：模拟器决定了一句
"最终答复"到底是提问还是收尾，而**只有收尾的那一句才被记为最终答复**，这直接影响
`verify_final_state`。两者都因此成为 `replay_trajectory` 的显式参数，且每次重放
构造新实例（它们持有会话级状态）。

## P1-6 方案 A：user simulator 与多轮澄清

用户于 2026-08-15 在方案 A（user simulator）与方案 B（工具面扩到 15+）之间裁定 **A**。

### 为什么模拟器是规则式的

本项目的评测契约要求确定性：固定 seed、固定预算、可重放轨迹、逐字节可复现的证据。
一个 LLM 模拟用户会让每次运行的用户侧输入都不同，`replay_trajectory` 直接失效，
配对比较也不再成立。规则式模拟器牺牲自然度，换来"这条多轮轨迹可以被逐字节重放"。
对一个以证据链为核心主张的项目，这个取舍没有第二个答案。

用 LLM 做模拟用户是可以的，但那必须是**独立的、不进发布判定**的探索轨道，
且要记录 provider / model ID / 采样参数——与 teacher 采集同一套纪律。

模拟器只回答**用户本来就知道的事**（任务 metadata 里的订单号），刻意不从
`expected_calls` / `target_state` 取值——那些是判定依据，从它们取值会让多轮变成泄题。

### 欠指定变体

`clarify` 开关把订单号从用户请求里拿掉，**真值一个字不变**：澄清改变的是"用户给了
什么"，不是任务本身。因此欠指定变体可以与基线变体直接对照。刻意只抽掉那一个必需
事实——同时抽掉多个变量就没法归因"它为什么失败"。

### 实测（12 条 qualification，纯 CPU，`policy_type=message_grounded`）

| 任务 | user simulator | 澄清任务 | 先问了 | 澄清率 | `task_success` | 平均轮次 | 可重放 |
|---|---|---|---|---|---|---|---|
| 不欠指定（对照） | off | 0 | — | — | **1.0000** | 2.17 | 1.00 |
| 欠指定 | off | 12 | 12 | 1.00 | **0.0000** | 1.00 | 1.00 |
| 欠指定 | **on** | 12 | 12 | 1.00 | **1.0000** | 3.17 | 1.00 |

三组对照缺一不可。只跑"开了模拟器之后 12/12"是不够的——那条断言在策略本来就能做对
时也会通过。必须同时证明：**(a)** 该策略在不欠指定的任务上本来就能做对；
**(b)** 欠指定 + 无多轮时它一条都做不成；**(c)** 接上多轮之后恢复。三者一起才说明
差值来自多轮通道本身。

**这度量的是机制，不是模型能力。** `message_grounded` 是**机制探针**：它只用
messages 里**用户说过**的信息决定动作，看不到订单号就提问。它不度量"模型会不会想到
要问"，只度量"问了之后系统能不能把答案送回来并继续"。真实模型的澄清能力需要 GPU
评测，**本轮没有做，也不声称**。

## 仍然成立的批评（未做，且不假装做了）

| 评审指出的 | 现状 |
|---|---|
| **工具面只有 3 个**（1 个是干扰项） | 未变。方案 B（扩到 15+ 含语义相近易混工具、画 tool selection 准确率随工具数的退化曲线）**被用户在 A/B 二选一中未选中**，未做 |
| `parser.py` 把多工具调用判 `multiple_tool_calls` 非法 | 未变。**禁止并行调用**仍然成立 |
| 文本 + 调用同时出现判 `mixed_tool_call_content` 非法 | 未变。这条还有连带约束：任何"先声明再执行"的数据方案都会把 `invalid_call` 从 0 打回去（LOG-20260811-06） |
| `GenerationSettings.enable_thinking` 强制 `False` | 未变。**禁止先思考再行动**仍然成立 |
| 用正则扫 `<tool_call>` 标签而不是走 OpenAI 兼容的 `tool_calls` 通道 | 未变 |
| 多轮**政策冲突**（τ² 的另一半） | 未做。当前的多轮只有"信息欠缺→澄清"，没有"用户要求与政策冲突→坚持政策" |
| `max_steps` 4–5 | 未变 |
| 无工具检索 | 未变 |

**parser 的并行调用与 thinking 限制是独立决策**，提示词明确要求不要"顺手一起改"：
它们会改变 `parser_id` 与生成契约，而两者都在配对字段里，牵动全部已有证据。

## 面试时怎么讲这一节

诚实的说法是：**Agent 本体从"最小 ReAct 循环"补到了"有政策注入、有独立 guardrail、
有可澄清多轮"的循环，但它仍然是单工具调用、无并行、无 thinking、3 工具的循环。**
每一条新增能力都有一组只差一个开关的对照实验和一个可复现的数字；每一条未做的，
在上表里点名。

比"我实现了 user simulator"更值钱的是：**为什么它是规则式的**（可重放性）、
**为什么对照要有三组**（否则断言在缺口不存在时也会通过）、以及**为什么一个新缝会
连带改变 replay 的前提**（运行条件必须能被重放复现）。
