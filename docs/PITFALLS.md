# 踩坑与根因总账

**目的**：把散落在十余份文档里的踩坑收进一张总账——每条给出现象、机制、教训与出处，
并把「最终指标为什么还不到」收敛成四层根因。**本文档是综合与索引，不是新读数的来源**：
每条数字的权威出处都在括号里，冲突时以出处文档为准。
**新增踩坑只追加，不改写**；本文档不进入发布判定，也不替代任何唯一事实源
（封存 holdout 观测台账见 `HOLDOUT_LEDGER.md`，阶段状态见 `EXECUTION_PLAN.md`）。

**建立日期**：2026-09-04。收入范围：R2–R10 全部已收口的踩坑。

## 一、四层根因：最终指标为什么还不到

发布候选 `sft-008` 的读数可以概括为：**模板内与同源措辞外都好；真正不好的是三处——
政策边界的稳定性（封存 120 上同配置两次运行分别 2 次与 7 次 `refund_denied_window` 违规）、
训练不可逐位复现（dev 58–60/60、违规 2 vs 7 差 3.5 倍）、
以及 GO 的 `success_delta_ci_lower` 只有 +0.0083（统计上无法拒绝零差异）**
（`POLICY_BOUNDARY.md`、`REBUILD_VERIFICATION.md`、`HOLDOUT_LEDGER.md`）。

四层根因按「直接制造这些读数的程度」排序：

### 根因 1（结构层）：数据切分在难度维度上不分层

冻结数据集按 `sha256(family)` 切 train 20 / dev 5 / holdout 10（每场景 35 个 family），
**切分完全不看难度**；而拒绝类场景的难度就是一个数——`margin`（`refund_deadline − current_day`
离判定边界 0 的距离）。实测偏移（`POLICY_BOUNDARY.md` §2）：

- `refund_denied_window` 的 margin ≥ 10（远超期）family 占比：**train 10% vs holdout 50%（5.0×）**；
  `refund_recovery` 4.0×；其余场景仅 1.0–1.3×。全部封存政策违规恰好落在 5.0× 那个场景。
- dev 的 margin 档覆盖缺口：`refund_denied_window` 只覆盖 4/7 档（缺 2、5、7），
  `refund_denied_duplicate` 只有 2/7 档，`refund_denied_ownership` 与 holdout 只交 3 档。
- **`offset = 0`（恰好到期、应放行）在 train/dev/holdout 里从未生成过**——判定分界点本身是空洞。

### 根因 2（方法层）：SFT 行为克隆学的是「表面触发器」，不是政策规则

- 训练数据是「状态 → 工具调用 → 结果 → 回复」的线性轨迹，模型学到的是
  「这 12 种说法出现时该退款」的触发器，不是「什么时候该退款」的语义判断。
  直接证据：`code_switch`（中英夹杂）1.00 → 0.00，换个口吻就不会了（`OOD_EVALUATION.md`）。
- 2×3 配对矩阵证明 prompt 与训练解决不同问题：prompt 修「不敢执行」（`refund_eligible`
  5→9/10），训练修「不会恢复」（`refund_recovery` 5→10/10），但**两者都不能教
  「理解用户真实意图」**——那是表达类 0/20 的根因（`RESUME_EVIDENCE.md` §1.5）。
- R7 的修复尝试证明单变量补数据有内在上限：补 margin 覆盖后探针与 dev 改善，
  但措辞分布外 `ood_dev` 0.9833 → 0.9500 退化，按事先规则判负——
  **补覆盖把决策边界整体推向「多拒绝」，是平移不是校准**（`POLICY_BOUNDARY.md` §6）。
- R8 归因权重：数据多样性不足 50%、SFT 方法论限制 30%、工程约束 20%（`R8_DIAGNOSIS.md`）。
  R9 Phase B 部分验证了前 50%：措辞多样性扩展后 OOD v2 0.8667、跨工具 OOD v4 0.8917，
  但代价是执行倾向（政策违规 7–8 次）——「多样性有帮助」成立且有代价（`R9_PHASE_B_RESULTS.md`）。

### 根因 3（工程层）：训练随机性 + 约束过紧，放大前两条

- **同 seed 重跑产出逐位不同的权重**（R5 发现，`REBUILD_VERIFICATION.md`）：
  dev 60/60 不是常数而是 58–60/60；封存违规 2 vs 7（3.5 倍）。margin 边界任务每格
  只有约 8 行训练数据，学不出稳定边界，运行间方差把边界点变成掷硬币。
- `max_steps=4` 太紧：`refund_recovery` 需要 3 次工具调用只剩 1 步余量，
  模型多说一句话就被判失败（`R8_DIAGNOSIS.md` 根因 3）。
- parser 禁止「文本 + 工具调用」混合（`parser.py` 的 `mixed_tool_call_content`），
  限制了数据形态多样性；`verify_final_state` 逐字段精确匹配；
  `refund_order` 的 `reason` 参数 4 选 1 精确匹配。

### 根因 4（流程层）：可迭代评测面饱和与封存纪律的两难

dev 60（58–60/60）与 `ood_dev` 60（0.9833、零违规）两个可迭代面都已饱和，
唯一能看见「该拒绝却执行」的封存集又不得反馈进开发——失败模式在方法上无从下手。
R7 建政策边界探针解决了一半（把失败定位到 `offset −14` 单一格），
但探针措辞与训练同源，**看不见措辞型退化**——这正是 R7 修复判负的机制
（`POLICY_BOUNDARY.md` §7）。

## 二、踩坑清单

每条格式：**现象 → 机制/教训 → 出处**。

### 数据与切分层

1. **训练/测试难度分布 5 倍偏移，全部违规集中在一条规则上**
   → 哈希切分不对难度分层；训练集中在「刚过期」，封存集一半是「远超期」。
   教训：**切分机制本身可以是分布偏移的来源**，数据量救不了切分。
   （`POLICY_BOUNDARY.md` §2）

2. **判定分界点 `offset = 0` 整个冻结数据集从未生成**
   → eligible 用 `20+margin`、denied 用 `20−margin`、margin ≥ 1，分界点结构性缺席。
   教训：**生成器的参数网格要在边界两侧对称覆盖，含边界点本身**。
   （`POLICY_BOUNDARY.md` §3）

3. **dev 看不见的失败，封存集上是 3.5 倍方差**
   → dev 每类只有 10 条 + 难度分布不同；同配置两次运行 dev 违规 2 vs 0、
   封存 120 上 2 vs 7。教训：**小样本迭代面的「零违规」不构成安全声称**。
   （`REBUILD_VERIFICATION.md`）

4. **teacher 不等于真值**
   → R7 状态增强采集 52/56 被接受，4 条失败**全部**是 DeepSeek 在最极端超期格
   违反同一条退款窗口规则。教训：teacher 数据必须过执行式 verifier 才能进训练，
   「大模型写的」不是质量证据。（`POLICY_BOUNDARY.md` §5）

5. **teacher 措辞的先验污染**
   → DENY 类场景用户请求写「请检查/执行」时 teacher 接受率 8%，
   改成「请评估是否可以」后 100%。教训：**指令措辞会预设结论**，
   采集模板要先分场景审措辞。（`progress.md` 2026-08-22 节）

### 方法与训练层

6. **12 句模板的表面形式过拟合**
   → 拿到封存 120/120 的候选在模板外 60 条掉到 0.5833，表达变化类 0/20
   比零训练基座（6/20）还差；20 条失败全部是 `premature_final_response`。
   教训：**模板内满分与泛化是两个断言**，必须各测各的。（`OOD_EVALUATION.md`）

7. **R6 措辞增强修复了表达类，但代价是执行倾向**
   → 修复后表达类 0.00→1.00、封存分片 0.9833–1.0000；同时封存违规出现
   2–7 次、`scenario_ood` 0.75→0.60。机制：模型更倾向执行。
   教训：**收益与代价同源，必须成对报告**。（`GENERALIZATION_FIX.md` §8）

8. **R7 针对性补数据判负：同源评测面高估收益**
   → `sft-009` 探针、dev 改善，`ood_dev` 退化；判读规则事先写定救了这个判定
   ——否则「探针修好了」就是结论。教训：**数据侧修复的验收必须同时给一个
   措辞分布外读数，且分布外退化优先于分布内改善**。（`POLICY_BOUNDARY.md` §6）

9. **复合动作能力缺口：`refund_then_cancel` 双订单 0/10**
   → gold 序列 `get_order(A)→refund(A)→get_order(B)→cancel(B)`，
   模型稳定执行成 `get_order(A)→get_order(B)→refund(A)→refund(B)`——把 B 也退款了。
   机制：语料中 refund 动作先验远强于 cancel；rtc oversample 占训练集 21% 时
   dev 反而从 4/10 恶化到 0/10。教训：**动作先验失衡不能靠 oversample 修**，
   需要提高 cancel 类 family 覆盖或构造中间辅助任务。（`R9_PHASE_B_RESULTS.md` §5）

10. **数据量的独立贡献至今没被测到**
    → R9 Phase A（240→1600 oversample）dev 0.983 但 OOD 评测因脚本未同步
    tool_call arguments 而失败；且 sft 行数 400→1600 时梯度步数 75→~300，
    「更多数据」与「训练更久」在设计里分不开。教训：**单变量消融要真的单变量**。
    （`GENERALIZATION_FIX.md` §8、`docs/handoffs/2026-08-21-r9-phase-b-execution-prompt.md`）

### 工程与复现层

11. **同 seed 重跑逐位不同**
    → 训练代码零改动、数据哈希一致，adapter SHA-256 不同；dev 波动 ±2 且全部落在
    `refund_recovery`。教训：**「训练不可逐位复现」必须写进口径**——
    头条数字一律区间化（58–60/60、113–117/120、0.9833–1.0000）。
    （`REBUILD_VERIFICATION.md`）

12. **退化曲线的自变量从未生效（`tool_count` 空转）**
    → 5 个断点 {3,6,9,12,15} 产出的任务逐条 `content_sha256` 相同、评测又对每个
    断点加载整份 15 工具 bundle——「曲线平坦」是恒真不是读数；四个逐位相同的点
    （0.45/0.70）本身就是缺陷指纹。教训：**冒烟门禁必须断言「不同断点的任务
    逐位不同」这类自变量生效性，而不是只断言流程跑通**。（LOG-20260827-01）

13. **评测集自己不自洽**
    → v3 评测集 Oracle 回放 110/120，两次提交把它改成 90/120——其中
    `skip_reads_gate` 让**任务数据可以关掉政策守卫**，`CANCEL_RECOVERY` 因此
    自己触发违规。教训：**gold 序列必须可解且零违规（Oracle 自洽测试），
    政策守卫不得由任务数据关闭**。（LOG-20260827-01）

14. **环境缺陷只有真实数据采集才暴露**
    → `environment.py::_get_order` 未暴露 `current_day`，窗口过期场景对推理式
    agent 不可解——静态测试全绿，teacher 全量采集时才发现。
    教训：**环境可解性与任务难度要用真实链路冒烟**。（`progress.md` 2026-08-06 节）

15. **system 消息换不掉且不报错**
    → teacher 轨迹的 system 消息来自持久化 metadata，改 `SYSTEM_PROMPT` 后重新导出
    238/240 条逐字节不变且不报错。教训：**常量要绑定期望哈希**
    （`sft_system_prompt_sha256` 声明期望值，「常量忘了改」成为硬错误）。
    （`progress.md` 2026-08-13 节）

16. **teacher client 从未设置超时**
    → 超时被归类为可重试，但构造 SDK client 时从未设超时（落 SDK 默认 600 s）。
    教训：**故障矩阵里每一类故障都要有对应的真实路径**。（`FAULT_MATRIX.md`）

### 评测与发布判定层

17. **GO 归因于部署形态，不是模型**
    → 同一份权重，未合并形态 p95 比值 1.92–2.03 FAIL，合并形态 1.02–1.13 过；
    延迟归因分离：单次调用 1.985×、调用次数仅 1.146×——代价来自全 linear LoRA 前向。
    教训：**引用 GO 必须同时说明是合并部署形态**。（`HOLDOUT_LEDGER.md`）

18. **120/120 不是泛化**
    → 拿到 GO 的候选在模板外 0.5833、表达类 0/20。教训：**引用 GO 必须成对给出
    分布外读数**——这条已由测试强制（`test_the_go_is_never_quoted_without_the_ood_reading`）。
    （`OOD_EVALUATION.md`）

19. **门禁比 delta 的盲区：绝对数在退步也能全绿**
    → 政策违规 11→7 通过 `policy_violation_delta ≤ 0`，但 7 次违规的候选照样
    拿 GO；`success_delta_ci_lower` +0.0083 几乎贴 0。教训：**相对门禁需要
    绝对下界补位**（v1.2 的 `ood_task_success_min ≥ 0.70` 是第一个绝对门）。
    （`HOLDOUT_LEDGER.md`、`release.py` v1.2）

20. **复合奖励掩盖执行退化**
    → `verifier_reward` 0.579→0.717 的同时 task_success 48/60→43/60——格式分量
    涨、执行能力跌。教训：**奖励与真值分开**，`verifier_reward` 已降级为诊断量、
    不得用于候选选择（`core/metrics.py` 头注）。（`PRODUCT_BRIEF.md` §差异化）

21. **dev 与封存集把同两次运行排成相反顺序**
    → dev 上 seed 1（60/60）更好，封存上 seed 0（117/120）更好。
    教训：**dev 不能替代封存集做候选选择的事后证据**——dev 已被用于选择，
    带选择偏差。（`REBUILD_VERIFICATION.md`）

### 流程与治理层

22. **对照基座选错，提升数字虚高**
    → A 的 +0.200 对照的是旧 prompt 的 base；新 prompt 零训练 base 已 54/60
    （`refund_eligible` 9/10）。「原本可以写提升 20 个点」。
    教训：**每条 delta 的对照点必须同 prompt、同条件配对**。（LOG-20260814-03）

23. **判读规则与冒烟门禁先于运行写定并提交**
    → R7 三分支判读、R9 判读线、R10 冒烟四条（全部与模型好坏无关）都在运行前
    提交。教训：**这是本项目防事后挑选的唯一机制，且多次救场**——
    预注册判负时没有讨价还价空间。（`task_plan.md` 各轮、LOG-20260819-01）

24. **「一个 seed 的效果」优先于「多个 seed 的方差」**（用户裁定）
    → seed 2 权重已训出但不评测不报告；取消预注册本身留痕。
    教训：**跑完不报告与事先取消是两件性质不同的事**，都要记录。
    （`task_plan.md` Task A、LOG-20260817-07 关联）

## 四、解决办法入口（2026-09-04 快照）

按性价比排序；前两条已在执行或已就绪，第三条判读规则已预注册待决策，
后四条为分析补充、需用户确认后才立项：

1. **退化曲线重跑**（进行中）：装置修复后小样本 teacher 采集已过门禁，
   GPU 阶段被 gpu-5090 驱动卡死中断，恢复后续跑（`docs/handoffs/2026-08-27-r10-degradation-rerun.md`）。
2. **OOD 集合进入发布门禁**（v1.2 schema 已就绪，fail-closed）：
   需不封存 OOD 开发集 + 封存 OOD holdout——把「引用 GO 必须带分布外读数」
   从纪律升级为机器强制，根治根因 4。
3. **R9 第四轮修 rtc**：方案甲 = cancel 类 family 20→30–35（单变量）；
   方案乙 = RTC 中间辅助任务课程；判读规则已预注册（`docs/handoffs/2026-08-23-r9-phase-b-round4-execution-prompt.md`）。
4. **DPO 入口门评估**：封存违规 2–7 次 + 探针可在 `offset −14` 稳定产生
   「该拒绝却执行」样本——失败数据入口门可能已满足；政策边界偏好对是 SFT
   补数据做不到的「边界校准」（针对根因 2）。
5. **训练方差治理**：固定剩余随机源，消「同 seed 逐位不同」；同时评估
   `max_steps` 4→6 放宽（R8 P1，低成本）。
6. **探针升级为二维迭代面**：政策边界 × 措辞池交叉网格，使迭代面同时看见
   边界型与措辞型退化，避免重演 R7「同源高估收益」（针对根因 4）。
7. **难度分层切分**（针对根因 1 的根治）：按 margin 分层冻结新数据集；
   代价是作废全部历史可比性，须作为新 dataset_version 走正式冻结流程，成本最高、最后决定。
