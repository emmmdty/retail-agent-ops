# 求职背景与项目组合约束

## 用户背景

- 985 院校研二，面向中国大陆 2027 届秋招，现在开始投递。
- 有一篇面向 CCKS 2026 的事件抽取论文，可证明研究训练；没有正式结果前不表述为已录用，也没有对口 Agent 实习或 Agent 论文。
- 求职方向不预设算法或开发偏好，优先选择与现有履历匹配且能在面试中完整解释的岗位。
- 每周可投入 30+ 小时；用户主要负责策略、方向、重大决策、验收和复盘，具体代码开发由 Codex/Claude 完成。
- 实验室共享 4× RTX 4090；默认单卡使用，长任务和多卡任务必须单独确认。
- 可使用阿里云、火山引擎等商业模型 API；成本不是硬约束，但所有运行仍需记录 token、费用和模型版本。
- 两个项目允许公开、重命名和大幅重定位，但本阶段不创建外部 GitHub 仓库。
- 最终产物是不产出论文的工程项目，判断标准是落地价值、工程闭环和求职解释力。

## 求职策略

主投岗位按以下优先级排序：

1. Agent 系统、平台、应用开发，Coding Agent 与 Agent Evaluation。
2. Agent 后训练、Agent 算法工程和评测算法工程。
3. 不把纯基础模型训练、纯 RL 研究岗作为主投方向。

项目组合固定为：

- **RetailAgentOps**：展示工具调用、领域数据、QLoRA 后训练、执行式评测、发布门禁和单卡部署。
- **SWEGate**：展示 Agent adapter、沙箱、可执行评测、证据链、CI 回归和 deploy/no-go 决策。

`03-deep-research-agent` 只作为现阶段简历过渡或补充项目；`04-research-project-agent` 暂停投入。

## 三个月节奏

- 第 1–2 周：两个项目各形成可运行、可展示的 v0.1，开始使用真实工程表述投递。
- 第 3–6 周：完成第一版工程闭环，形成可量化简历材料和面试演示。
- 第 7–9 周：只依据失败分类优化，不提前押注新算法或大系统。
- 第 10–12 周：完成跨模型/任务验证、公开文档、演示视频、简历和面试问答。

时间估计按“决策门禁到可验证产物”的日历时间计算，不按代码行数或 Codex 生成速度计算。普通纵向切片预计 2–4 个日历日；远程训练或批量评测另加 1–3 日。

## 证据与简历纪律

- 只写实际运行得到的任务数、成功率、违规率、延迟、成本、显存和发布结论。
- 不写 SOTA，不把内部固定子集写成官方排行榜，不把单次成功演示写成生产稳定性。
- 项目可以输出 `NO-GO`；能够拒绝不合格候选本身是发布系统的工程价值。
- 用户每周至少完成一次核心模块代码走读和一次脱稿架构讲解，确保能解释数据流、失败路径、替代方案和限制。
