# ADR 0005: 评测集按哈希切分，不由人挑；且必须留一个只观测一次的分片

- 状态: 已接受
- 日期: 2026-08-17
- 关联: LOG-20260816-01（OOD v1 打掉了 120/120）、R6 泛化修复

## 背景

2026-08-16 的外部审阅在「我会追问什么」里留了一条：

> 你的分布外集合是**知道失败模式之后**由你自己手写的，而且它不封存。
> 什么东西能阻止下一轮迭代对着它调？

这条批评成立，而且当时**没有机制性的回答**——`domain/ood_tasks.py` 的 60 条是作者手写的
模板库，靠的是「我保证不拿它选候选」。同一轮审阅还指出另一件相关的事：项目的
`expression_ood` 从 0.30 掉到 0.00，**有观察没有诊断**。

R6 要同时解决这两件事：既要修那个失败，又不能在修的过程中把评测集变成第二个训练集。

## 决策

**今后任何用于判断泛化的评测集，必须满足三条：**

1. **素材由确定性哈希切分，不由人挑。**
   `phrasing_bank.assign_partition` 只看 `sha256(措辞文本 + 固定盐)`，
   与场景、风格、生成顺序、以及「这条好不好改」全都无关。
   盐是冻结量，改盐等于换一个实验。
2. **训练用的素材与评测用的素材逐条互斥，由代码断言。**
   `assert_partitions_are_disjoint` 在加载时执行；
   `ParaphrasePlan` 在构造时拒绝任何非 `train_aug` 的分片，
   `_ood_phrasing_spec` 在构造时拒绝把 `train_aug` 当评测集。
3. **必须留一个 `*_sealed` 分片，只观测一次**，且观测发生在
   所有迭代结束、代码冻结并提交之后。迭代只允许用 `*_dev` 分片。

**连带的第四条：素材的语义必须双向校验。** 生成之后要反过来让模型把它分类回原意图，
不一致即丢弃。只做结构校验（有没有占位符、长度）挡不住「把拒绝类写成了执行类」，
那种样本会静默污染真值。

## 结果

- **「泛化」这个词有了可检验的含义**：指的是「对同一生成器产出的、训练从未见过的
  措辞的鲁棒性」。这比「对任意真实用户输入的鲁棒性」弱得多，但它是**可以被证伪的**，
  而且证伪它的那个分片在做出声称之前只被看过一次。
- 手写的 OOD v1 **保留**，但改变角色：它是**不同来源**的独立迁移检查，
  且**不得用于任何候选选择**。作者不同、生成过程不同，因此它对 v2 是外部验证。
- 代价是评测集不再能被随手扩充——加素材要重跑生成、重算哈希、重排分片，
  而重排分片会改变 `bank_sha256`，等于换一个实验。**这个摩擦是有意的。**

## 一条必须一起记的相关判断

审阅还问了：「GO 来自合并 LoRA，那你的延迟门禁到底在测模型还是在测你自己的服务代码？」

**测的是部署产物，这是对的**——上线的是产物不是权重。
项目的错误不在门禁，在**叙述**：前三次观测把一个部署实现的开销读成了模型能力的结论。
纠正之后的口径是：`p95_latency_ratio` 属于**部署门禁**，
它的变化必须先归因到部署形态再谈模型（LOG-20260815-01 的单次调用 −46% 就是这条的产物）。

## 弃选方案

1. **继续手写评测集**：省事，但「什么阻止你对着它调」没有机制性回答，
   而这个项目卖的就是纪律。
2. **让 LLM 直接生成整个任务集（含状态与真值）**：真值来源与评测对象同源，
   一旦模型有系统性偏见，偏见会同时进真值和读数。R6 只让 LLM 生成**用户怎么说**，
   状态、期望调用与判定逻辑全部沿用已冻结的 `_scenario_contract`。
3. **把 OOD 直接做成发布门禁**：诱人但过早——OOD 集合本身会不会被过拟合尚无答案，
   而门禁一旦加上就很难在不被质疑「照着结果改门禁」的情况下调整。
   先做成必看读数，等有两代独立 OOD 集合的对照之后再谈门禁。
